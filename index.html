Coding Plans

        
国内外套餐对比

        
正在统计档位…套餐和工具是两件事：工具是壳，套餐是电。同一个壳可以换不同套餐，反过来也一样。国际档位按 $1 = ¥7.25 折算，仅用于同表比较。

        

      


      

        
◎先说清你要什么

        
不同用法对「价格 / 额度 / 稳定性 / 合规」的权重完全不同。

▣如果只买一个订阅

          
按量 API 综合分常常最高，但很多人要的是「月底账单固定」。这里只比订阅档。

          

        

        

          
▦按量 vs 订阅，怎么选

          
    
            
  • 按量适合：用量波动大、要进 CI、要接自建脚本、讨厌被白名单限制。代价是账单没上限。
    • 
            
  • 订阅适合：每天稳定用、讨厌看账单、想一次付完不管了。代价是额度窗口和工具白名单。
    • 
            
  • 最优解通常是两个都要：订阅做日常主力，按量做兜底和批处理。加起来常常还比一个 Pro 档便宜。
    • 
          

        

      


      

        

          ▤按工具看阶梯＋
        

        
同一家的档位排在一起，才看得出「加钱买到了什么」。价格是当前核验值，点上方地区可只看国内或国际。

        

      


      

        

          
◈只选一个，选哪个

          
    
            
  • 要通用、要试错便宜：火山方舟 Lite ¥40。一个订阅六家模型，工具白名单最宽，首月 ¥9.9。缺点是高峰 429，别把线上回归压在它身上。
    • 
            
  • 要工具生态最全、能接 Claude Code：GLM Coding Lite ¥118。支持 20+ 工具，但 2026-07 涨过一次 140%，且数据可能用于训练。
    • 
            
  • 要极致便宜、能自己写脚本：DeepSeek API 按量。没有月费，用多少付多少，闲时半价。适合当兜底和批处理。
    • 
            
  • 要合规、代码不出境：优先国产模型 + 自建壳（DSH / MiMo Code），别碰明确写「数据用于训练」的套餐。
    • 
          

        

        

          
!四个容易踩的坑

          
    
            
  • 套餐 ≠ API 余额。绝大多数 Coding Plan 只能在白名单工具里用，写个 Python 脚本直接调是不行的。要脚本调用，得单独买 API。
    • 
            
  • 「不限量」都有滚动窗口。5 小时窗口 + 周窗口是行业惯例，跑长任务时会被卡在窗口边界上。
    • 
            
  • 首月价不是价格。¥9.9、¥7.9、¥24.5 都是首月，第二个月恢复原价。做预算按标准价算。
    • 
            
  • 涨价没有承诺。GLM 24 天内涨了 140%。任何「长期锁定」的说法都要看合同条款。

                    Data / 01
                    
        
                    数据健康
                    
        
                    这一页不新增数据，只把已有的核验日、抓取结果、过期项和导出入口摆在一起。目标很简单：任何一条价格，你都能在 10 秒内判断「新不新、谁该去核、能不能拿走」。
                    
        
                    
      
                    
      
                    
      
                    
        
                    
          
                    ◷核价与抓取待办
                    
          
                    按「影响金额 × 超期天数」排序。复制成 Markdown，直接贴进周会或 issue。
                    
          
                    
          
                    
        
                    
        
                    
          
                    !自动更新源健康
                    
          
                    失败不隐藏，按错误类型分组。连续失败 2 次的源会被标红。
                    
          
                    
          
                    
          
                    
        
                    
      
                    
      
                    
        
                    ⇢发现哪条不对？
                    
        
                    这一页的用处是让「哪条可能过期」浮出来；真发现错了，就地报——比发邮件快，也比发邮件留得下证据。
                    
        
                    
      
                    
      
                    
        
                    ⌘这些数字怎么来的
                    
        
                      
          
                    • 新鲜度：取 meta.lastVerified；超过 staleAfterDays 标黄，超过两倍标红。
                      • 
          
                    • 核验覆盖：套餐的 verified 字段；缺失即进入待办，不按「应该核过」估算。
                      • 
          
                    • 源健康：最近一次 refresh.js 的 _refresh-report.json；失败按 HTTP / timeout / TLS 分组，不吞错。
                      • 
          
                    • 将过期：免费额度的 expiry 在 30 天内；已过期的保留在列表里做证据。
                      • 
          
                    • 导出：构建期由 build.js 生成，和页面同源；不提供「猜测字段」。
