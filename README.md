一个**可以长期用下去**的站点：对比 29 款 AI 工具、57 档国内外套餐、32 套组合方案，
外加 20 项能力图谱、4 道题的测试人诊断、30 条 AI 评测用例、11 个测试角色，
以及一份可打印的决策报告。数据健康可见、数据集可下载、结论可交付。

> 站内数字（工具数、套餐数、价格区间）全部由 `data/*.json` 在运行时算出来，
> 增删条目后不用改模板文字。

不是一次性报告。价格会变、模型会换代，所以这里拆成「数据 + 模板 + 构建」三层，
**改 JSON、跑一条命令、刷新页面**，就能更新。数据过期了页面自己会提醒你。

## 信息架构（v6：选型 → 角色 → 变局 → 可信 / 可交付）

首页仍然是 **#home 诊断台**。v5 把问题域从「买什么」扩到「我在哪、行业在变什么」；
v6 再补上「数据还能不能信、结论能不能交出去」：

- **首页**：左栏一句 h1 + 两个按钮 + 三步路径轨 + 数据状态行；右栏 DIAG 引擎三问出报告。
  报告态含：PASS 章、方案名、**壳/电/合计三段成本**、理由、额度判断、风险、升级路径、四个出口。
- **读数带**：功能入口 / 工具档案 / 最低月成本 / 市场变动，全部来自数据文件。
- **七个模块，24 个功能页**：
  开始与总览（2）· 诊断与判断（4）· 角色与成长（5）· **变局与大事（2）** ·
  工具与方案（4）· 选择与资源（4）· 数据与更新（3）。
- **v6 新增三页**：
  - `#health` **数据健康**：新鲜度、套餐核验覆盖、自动更新源成功率、核价与抓取待办、
    6 个数据集导出。失败源按 HTTP / timeout / TLS 分组，不吞错。
  - `#evalset` **AI 评测集**：30 条可直接抄走的验收用例，六类各 5 条（功能 / 边界 / 注入 / 越权 / 回归 / 成本），
    每条含输入、预期、判定器、严重级别；可筛选、搜索、复制、下载 JSON。
  - `#report` **决策报告**：把诊断、已选组合、四项自检、30 天动作、风险边界收成一份 A4 报告（打印约 2 页）；
    支持打印 / 保存 PDF、复制 Markdown；无方案时给空态引导。
- **v5 新增四页**：
  - `#news` **AI 大事**：32 条人工核过 + 31 条自动抓取；国内/国外、模型/产品/价格/政策/资本/安全；
    人工条目必须写「对测试的影响」，自动条目单独标记、默认不显示。
  - `#impact` **AI 对测试的冲击**：8 组调研数据、9 项活动的替代度、90 天三段方案、6 条反模式、5 题自检。
  - `#roles` **测试角色阶梯**：7 个执行层角色 × 初/中/高，加工具开发 / 平台开发 / AI 测试开发 / AI 全栈；
    「用 AI 测 / 测 AI / 与 AI 协作 / 防 AI 风险」四象限。
  - `#free` **白嫖地图**：34 条免费额度，四类；每条写清怎么领、上限、坑、过期；含 3 条反面案例与 1 条已过期活动。
- **旧 hash 全部保留**（`#tools`、`#plans`、`#persona`…），旧链接零失效。
- **完整工具站（#all）**：24 行规格表，一行一个功能（序号 / 名称 / 一句话 / 模块 / 直达）。
- **顶部主导航**只放大模块入口；「我的」下放决策报告 / 我的判断 / 我的组合 / 执行包；
  「更多」下放 AI 大事 / AI 冲击 / 角色阶梯 / AI 评测集 / 白嫖地图 / 数据健康 / 更新日志 / 数据源。
- **移动端**汉堡是分层面板：主链接 → 模块 accordion → 功能。
- **埋点**：`track()` 写 localStorage（`ats_events`，上限 500 条），`atsTrackDump()` 导出。

## 订阅形态（form）说明

国内订阅已经分化成五种形态，**计费单位完全不同，混在一起比价是错的**：

| form | 名称 | 计费单位 | 代表 |
|---|---|---|---|
| `coding` | Coding Plan | 请求次数 / 积分 | 火山方舟 Lite、GLM Coding |
| `token` | Token Plan | Credits 统一抵扣 | 百炼、MiniMax、小米 MiMo |
| `agent` | Agent Plan | AFP 积分（含多模态 + 工具链） | 火山方舟 Agent Plan |
| `member` | 会员制 | 与产品会员共享额度池 | Kimi 会员、Qoder |
| `paygo` | 按量 API | Token 实际用量 | DeepSeek API |

每个套餐必须带 `form`、`quotaUnit`（单位）、`window`（计费窗口）、`overage`（超限出路）四个字段，
构建时会校验，缺了会报错或警告。

## 组合方案（bundles.json）

工具和套餐分开选容易选错，所以单独有一层「成品组合」。每套要写清楚：

```json
{
  "id": "b_dsh_volc",
  "tool": "dsh",              // 必须存在于 tools.json
  "plan": "volc",             // 必须存在于 plans.json
  "monthlyCost": 40,          // 开源壳算 ¥0，只算套餐价
  "costBasis": "DSH 开源免费 + 火山 Lite ¥40",
  "s": { "coding": 8.5, "value": 9.5, "flex": 9.0, "cn": 9.5, "ci": 8.0, "test": 8.0, "ease": 5.0 }
}
```

七个维度：编码能力 / 性价比 / 灵活性 / 国内体验 / CI 友好 / 测试适配 / **上手难度（ease）**。

`ease` 很关键——没有它，「新手友好」和「要进 CI」会选出同一套组合，那就等于没筛。
页面用的是**先硬筛后排**：新手画像直接排除纯命令行方案，而不是只调权重。

## AI 测试专项（aitest.json）

这是这个站和别的对比站最不一样的一页。别的站都在比「谁写代码强」，这里按
**「能不能把测试这件事跑起来」**来分。

每个工具必带 `maturity` 字段，只能是三个值：

| maturity | 含义 | 能不能进生产 |
|---|---|---|
| `stable` | 已经在真实项目里能用了 | 可以 |
| `beta` | 能用，但边界场景要人盯 | 谨慎，先小范围 |
| `experimental` | 别放进生产流水线 | 不行 |

构建时会校验这个字段，写错会直接报错。加新工具时别客气，如实标 `experimental`——
一个被高估的工具比没有这个工具更糟。

## 额度计算器

在「我的组合」页底部。输入每天几小时、每小时几轮、上下文规模、跑批占比，
估算 12 个套餐够不够用。

**它故意不给精确值。** 各家的额度单位（请求次数 / Credits / AFP / 共享池）根本无法互相换算，
所以它做的是：先算出「你大概需要多少 token」，再按每家的口径折算出占用比例，
最后给三档结论（够用 / 刚好 / 不够）。

真正准的答案只有一个办法拿到：买最便宜的一档，用两周真实工作流压一遍，记下每天撞几次额度。

## 优惠与免费额度（promos.json）

「优惠白嫖」页的数据源。选型的真实顺序是**先白嫖 → 再首购 → 最后才谈续费**，这一页补的是前两步。

四个数组对应页面的四块：

| 字段 | 内容 | 条数 |
|---|---|---|
| `freeTier` | 各家免费额度：怎么拿、限制、坑在哪 | 7 |
| `firstBuy` | 首购优惠：原价 / 优惠价 / 条件 / 截止 / 到期后 / 可否叠加 | 8 |
| `stacking` | 四层叠加结构（L0 白嫖 → L1 首购 → L2 邀请 → L3 赠金） | 4 |
| `offpeak` | 省钱时段：GLM 非高峰 5 折、百炼夜间 0.4× 等 | 6 |

**每条 `freeTier` 都必须写 `trap`（坑在哪），少于 15 字构建会失败。** 只讲好处的那是广告，这一页的价值在于「你以为能白嫖但其实不行」的那些细节——比如百炼的 Token Plan 专属 API Key 根本不消耗免费额度。

`firstBuy` 的 `list` 与 `promo` 都必须是数字且 `promo <= list`，页面用它们算折扣幅度并染色（≥50% 红、≥10% 黄、其余灰）。**表里同时给「到期后」价格**，是为了防止有人拿首购价做长期预算。

`offpeak` 里 `save` 字段如果写「不省钱」或「省心」，页面会渲染成灰色徽章而不是绿色——火山 Auto 的路由优化就是这种情况，它不是折扣。

## 市场变动（events.json）

价格表是快照，这张时间轴才是趋势。**只记录有官网链接能对上的变动**——价格没变不代表没变过，
只是没查到确证。宁可不写，也不写「据说」。

支持的 `kind`（构建时会校验）：

| kind | 含义 | 例子 |
|---|---|---|
| `price` | 涨价 | GLM Lite ¥49 → ¥118（+140.8%） |
| `cut` | 降价 | — |
| `retire` | 停售 | 百炼 Coding Plan Lite 停新购 / 停续费 |
| `form` | 形态调整 | 百炼从按请求次数改成按 Credits |
| `launch` | 上线 | 火山方舟发布 Agent Plan |
| `model` | 模型下线 | 小米 MiMo-V2.5 系列下线 |

**什么不记**：额度缩水（没有公开数据）、首月价/活动价（那是入口价不是价格）、
没查到来源的传闻。

## 价格轨迹

用 SVG 手写折线，不引第三方图表库——为了一个 78px 高的小图引 200KB 的库不划算。

画之前会先过滤 `price <= 0` 的记录。这条很关键：`dsapi` 早期 history 里有个 `price: 0`，
那表示「按量计费不是订阅」，直接画会被读成「降到 0 元」。

只有 1 个数据点的套餐画不出趋势，会单独列在「只有单点记录」里，不硬画成一条水平线。

## 两两 PK

排行榜告诉你「谁第一」，PK 告诉你「这两款差在哪」。

- 九维对比：差距 ≥1 分才标绿/红，1 分以内算持平（避免 0.5 分的噪音）
- 20 项能力对比：差距 ≥2 分才标「明显领先」，1 分标箭头，0 分标等号
- 结论区会给「为什么赢」——找出权重放大后差距最大的两维，而不是只说总分高
- 选了两款一样的工具时会直接提示，不会算出「领先 0 分」这种废话

## 测试人诊断（persona.json）

4 道题，8 种类别。核心思路：**同一个工具对不同处境的人价值完全不同**，
所以先问「你现在什么样」，再给建议。

8 个类别（带点恶趣味，但每种都对应真实处境）：

| 类别 | 典型状态 | 对应组合 |
|---|---|---|
| 🐹 点点点仓鼠 | 全靠手工，学自动化屡战屡败 | Qoder + 专业版 |
| 🦫 脚本苦力海狸 | 有脚本但易碎，80% 时间在修 | DSH + DeepSeek API |
| 🦊 工具收藏家狐狸 | star 了五百个，跑通三个 | DSH + 火山方舟 Lite |
| 🐙 章鱼多线程 | 进了 CI，但天天救火 | Hermes + DeepSeek API |
| 🦉 深夜猫头鹰 | 团队里唯一会写代码的测试 | Pi + DeepSeek API |
| 🐜 数据蚂蚁 | 造数据三小时，测十分钟 | MiMo Code + Token Plan |
| 🦁 带队狮子 | 一周五份报告，没时间看代码 | DSH + 百炼 Token Plan |
| 🐧 抱团企鹅 | 推团队体系，合规优先 | DSH + 百炼 Token Plan |

### 加新类别时要注意的三件事

1. **必须可到达。** 构建时会检查每个类别的 key 是否至少出现在一个选项的 `scores` 里，
   没有的话直接报错——不然你加了个永远选不出来的类别。
2. **分数要调平衡。** 第一版跑下来 beaver 占 38.7%、ant 只有 1.2%，
   说明题目没真正区分开。改完要穷举 256 种组合验证分布。
3. **并列第一要有确定规则。** 代码里用 `PERSONA_ORDER` 固定优先级打破平局，
   保证同样答案永远得到同样结果。

### 为什么答完才显示结果

不做「边答边变」的实时反馈，因为那会诱导用户为了看到想要的类型而改答案。
另外结果页会明确写「4 道题不可能定义一个人」「类别会变」「没有高级低级」——
诊断的价值是帮你找到下一步，不是给你贴标签。

## 怎么更新数据

### 只改内容（最常见）

1. 打开 `data/plans.json`，改 `price`、`quota`、`models` 这些字段
2. **顺手改 `verified` 为今天**（`"2026-10-29"`）
3. 跑 `node build.js`
4. 刷新浏览器

价格历史建议记在 `history` 数组里，页面上的走势会用到：

```json
"history": [
  { "date": "2026-05-01", "price": 49,  "note": "原 Lite 价" },
  { "date": "2026-07-31", "price": 118, "note": "涨价 140.8%" }
]
```

### 加一个新工具

在 `data/tools.json` 里追加一条。必填字段看现有条目照着写：

| 字段 | 说明 |
|---|---|
| `id` | 唯一标识，英文小写 |
| `name` / `vendor` / `tagline` | 显示用 |
| `score` | 9 个维度各 1–5 分，**必须和 `criteria.json` 里的 `criteria[].id` 对齐** |
| `capabilities` | 20 项能力分，**必须和 `capabilities.json` 对齐** |
| `tags` | 数组，缺了会导致页面白屏 |
| `link` / `verified` | 来源链接、核验日期 |
| `provenance` | 各字段的来源等级（官方 / 实测 / 社区 / 推断） |

### 分数来源等级

主观评分最容易被质疑，所以每个分数都标了它是怎么来的：

| 等级 | 含义 |
|---|---|
| `official` 官方 | 官方文档/定价页明写（价格、可用性、许可证） |
| `measured` 实测 | 本人实测或有可复现的外部跑分 |
| `community` 社区 | 社区反馈汇总（issue / 论坛 / 博客） |
| `inferred` 推断 | 根据架构与公开信息推断，未经实测 |

页面上这些以彩色小方块显示（官 / 测 / 社 / 推），悬停看说明。工具抽屉里有「分数是怎么来的」一栏，
逐个字段列出等级。

构建脚本会做校验，字段缺失会直接报错并指出是哪一条，不会静默生成坏页面。

### 调整评分权重

`data/criteria.json` 里的 `profiles` 是用户画像预设。每个画像给 9 个维度各一个权重（0–10），
页面上的「综合分」就是 `Σ(权重 × 分数) / Σ权重`。

想加一个画像（比如「外包驻场」），复制一份改名字和权重即可，页面会自动多一个按钮。

## 自动更新与数据检查

```bash
node scripts/refresh.js              # 抓 12 个 RSS + 14 个价格页指纹，写盘
node scripts/refresh.js --dry        # 只打印差异，不写盘
node scripts/refresh.js --offline    # 不联网，只做新鲜度报告
node scripts/refresh.js --only=news  # 只跑新闻
```

分三层，可靠性依次下降，所以分开报告：

| 层 | 检查什么 | 可靠性 | 会不会自动改数 |
|---|---|---|---|
| **L1 新鲜度** | 每个数据集最后核验日、距今天数、是否 >30 天 | 100% | 否 |
| **L2 新闻 RSS** | 12 个官方/媒体源，关键词过滤 + 标题去重 + 标题党过滤 | 高 | 只写 `news-auto.json`，不碰人工条目 |
| **L3 价格指纹** | 14 个定价页的文本哈希与价格串快照 | 尽力而为 | **只告警，不改价** |

**为什么不自动改价**：自动解析会把「$20 起」读成「$20」，把「原价 ¥60」读成「现价 ¥60」。
抓错一个价格，比不更新更糟。所以价格层只做两件事：发现页面变了 → 在「数据源」页标记「有变化，去核价」。

**自动更新的边界**：
- 人工核过的 32 条新闻永远优先，自动条目永远单独标记、默认不显示；
- 抓取失败的源照实写进运行报告（403 / 404 / timeout 都保留），不隐藏；
- 没有任何一条自动逻辑会改 `tools.json` / `plans.json` / `promos.json`。

`data/_refresh-report.json` 是最近一次运行的真实结果；`data/_price-snapshots.json` 是价格页指纹。
`.github/workflows/data-refresh.yml` 每周一 09:10（北京时间）跑一次，重构建 + 跑门禁，有变化才提交。

**数据健康页**（`#health`）把上面三层收成一页：上次核验距今天数、套餐核验覆盖、RSS/定价页成功率、
失败源按错误类型分组、核价与抓取待办（可复制 Markdown）。构建还会生成 `exports/` 下的
`tools.json`、`plans.json`、`plans.csv`、`plans.md`、`evalset.json`、`manifest.json`，
页面直接链过去，数据不锁在单文件里。

## 页面上的几个概念

**综合分**：不是「谁最好」，是「在你这组权重下谁最好」。换画像、拖滑块，排名会变。
默认权重偏向 AI 测试开发场景。

**夺冠率分布**：矩阵页有一块「随机权重下谁能夺冠」。逻辑是固定种子抽 2 万组权重
（每维 0–10 均匀），统计每款夺冠的百分比。它回答的是「这套评分表有没有被某一款吃死」——
如果某款在任何权重下都赢，那「换权重排名会变」就是假的。这块还会跟着滑块实时重算
「你当前偏好附近」的那一列（当前权重上下 ±3 浮动），所以你能看到自己的偏好把冠军
集中到了谁身上。

**构建门禁**：`build.js` 里有同一套蒙特卡洛检查。**任何一款工具夺冠率 > 40%，或能夺冠的
工具少于 4 款，构建直接 exit 1** 并打印完整分布。改分数时如果又调出个「全场通吃」，
构建会拦住你，而不是让页面悄悄退化成一张假对比表。

**数据已核验 N 天前**：由 `verified` 字段和 `meta.json` 的 `staleAfterDays`（默认 30 天）算出来。
超过阈值页面会标黄提醒。这个标记和抓取脚本成功与否无关——即使全抓失败，你也知道数据有多旧。

**为什么 Claude Code 在「极客自建」和「海外无限制」两个画像下排第一**：
它工具生态和模型能力确实最强，但那两个画像的前提是「不在乎国内可用性」。
如果你在国内、要用人民币付款、要稳定直连，这个前提就不成立，排名会变。

### 2026-10 的那次分数校准（为什么 DSH 不再是「默认第一」）

初版评分有个系统性问题：DSH 的 9 个维度里 5 个并列全场最高、最低分是 3（全场唯一），
20 项能力里 0 个红格、19 个绿格。结果随机抽 2 万组权重，DSH 夺冠率 **96.07%**，
Claude Code 3.36%——而页面还在说「换权重排名会变」。用户一拖滑块就发现是假的。

这次校准只动「有事实依据」的分，没有加噪声：

| 工具 | 维度 | 改动 | 依据 |
|---|---|---|---|
| DSH | 工具插件生态 | 3 → **2** | 第三方插件 / 社区模板量远低于 Claude Code、Codex；官网无插件市场 |
| DSH | 模型编码能力 | 4 → **3** | DeepSeek-V4 在跨文件复杂重构、长上下文一致性上落后 Claude / GPT 一线 |
| DSH | 自动化可编排 | 5 → **4** | 无云端并行沙箱，子代理只能串行跑；Codex 的云端并行是独一份 |
| DSH | 长期演进 | 4 → **3** | 技术预览期接口仍在变，社区规模小，可迁移性待验证 |
| DSH | 上手难度 | 4 → **3** | 需自备 API Key + Node 环境，不是下载即用的图形化产品 |
| DSH | 测试工程适配 | 4 → **3** | 三个测试能力项（接口 / UI / 缺陷归因）都是 4，低于 Claude Code 的 5 |
| Claude Code | 测试工程适配 | 4 → **5** | 接口自动化、UI 自动化、缺陷归因三项能力分都是满分 5（Playwright MCP 现成），决策分打 4 与自己的能力表自相矛盾 |

DSH 的 20 项能力分同步下调：需求分析 / 用例生成 5→4、代码理解与重构 4→3、
多智能体 4→3、插件生态 3→2。校准后 DSH 有 4 格 ≤3、0 格高于全场最高。

同时修了一个反向问题：Claude Code 的测试适配被低估了 1 分，改回 5。

**结果**：全局夺冠率 DSH 96.02% → 25.36%，Hermes 23.94%，Claude Code 20.40%，
Qoder 17.95%，ZCode 9.25%，MiMo 2.58%——没有哪款超过 40%，6 款能夺冠。
这个结论现在由 `build.js` 的门禁守住，不是靠人记得。

## 分享链接（URL 状态）

调整出来的结论可以直接发给别人。权重、画像、诊断答案、选中的套餐都压进 hash，
对方打开看到的和你眼前的是同一份。

```
#matrix?p=geek                  打开「极客自建」画像
#matrix?w=0-7-9-7-6-9-10-6-4    自定义权重（9 个数字对应 9 个维度，短横线分隔）
#persona?pe=aaaa                直接看诊断结果（4 个字母 = 4 道题各选第几个选项）
#plans?pk=dsapi                 套餐页高亮到 DeepSeek API
```

规则是**只写改过的部分**：权重等于画像默认值时不写，画像就是默认的 `aitest` 时不写，
没做诊断不写 `pe`，没选套餐不写 `pk`。所以全默认时 URL 就是干净的。

侧栏底部的「复制链接」按钮会先同步再复制。`file://` 下浏览器常常拒绝剪贴板权限，
这时会退回到一个手动复制的输入框——不是 bug。

坏参数一律忽略退回默认，不白屏（`w=999` / `p=nope` / `pe=zzzz` / `pk=nope` 都测过）。

## 无障碍

- 第一个 Tab 停靠点是「跳到主内容」，聚焦时从左边缘滑出
- 所有可聚焦元素有 2px 青色焦点环（`:focus-visible`）
- 尊重 `prefers-reduced-motion`，开启动画减弱时跳过过渡
- **两套主题都通过 WCAG AA 对比度检查**（正文 4.5:1、大字 3:1），见下

### 对比度是怎么保证的

浅色模式不是「把背景调白」就完事——大量文字原本是给深色底写的亮色，换到白底
就直接看不见了。所以这里用变量分层而不是逐条 `!important` 打补丁：

| 变量 | 用途 | 深色 | 浅色 |
|---|---|---|---|
| `--cyan` `--blue` `--violet` `--amber` | 背景、边框、渐变、装饰条 | 亮色 | 保持亮色 |
| `--cyan-t` `--blue-t` `--violet-t` `--amber-t` | **只给文字用** | 与主色相同 | 加深版 |
| `--c1` ~ `--c7` | 原先写死的十几个十六进制亮色 | 亮色 | 加深版 |
| `--dim2` | 次级说明文字 | `#7f8fa9`（5.4:1） | `#5b6a80` |

规矩只有一条：**写 `color` 一律用 `-t` 结尾或 `--cN`；写 `background` / `border` /
`linear-gradient` 一律用不带后缀的主色。** 新增组件照着这个来就不会翻车。

内联 `style="color:…"` 也要用变量——内联优先级最高，类选择器改不动它。

改完可以自己验：

```bash
node scripts\a11y-audit.js      # 输出 {"dark":{"total":0},"light":{"total":0}} 即通过
```

**这个脚本曾经一直在骗人。** 2026-10-30 那次改版才发现它有三处漏检，修好之后从
「0 个问题」变成「深色 39 处、浅色 53 处不达标」：

| 原来的写法 | 后果 | 现在 |
|---|---|---|
| `querySelectorAll('.view.on *')` | 侧栏、抽屉、命令面板、过期提示条全在视图外，一个都没扫 | `body *` |
| `textContent.trim().length > 1` | 热力图每格只有一个字符，274 格全跳过（它们的字色当时全是错的） | `> 0` |
| 跳过所有 `backgroundImage !== 'none'` | verdict 卡、note 块、组合卡头部全部漏检 | 仍然跳过（渐变算不出单一底色），但这几类要人工复核 |
| 没有 `::placeholder` 检查 | 搜索框占位符从没被测过 | 单独查一遍伪元素 |
| 去重键只用了选择器 | lv1~lv5 五档只会报一条 | 键里带上背景色 |

**教训：验收脚本自己也要被验收。** 一个只会输出 0 的检查器，和没有检查器是一样的——
区别是它会给你虚假的安全感。

探针会沿 DOM 往上找每个文字元素的真实底色（把半透明层依次合成），按 WCAG
相对亮度公式算比例，两套主题 × 16 个页面全扫。它对**自带渐变背景的元素会跳过**——
那种元素算不出单一底色，强行算会误报。

### 设计系统：三条数值规矩

改版时把发散的值收敛了一遍，现在只剩这几档。**新增组件请直接用变量，不要写新数值。**

| 类别 | 档位 | 变量 |
|---|---|---|
| 字号 | 11 / 12 / 13 / 15 / 18 / 22 / 27 / 36 | `--fs-1` ~ `--fs-8` |
| 字重 | 400 / 600 / 700 | 无变量，直接写 |
| 圆角 | 6 / 10 / 14 | `--r-sm` / `--r-md` / `--r-lg` |
| 间距 | 4 / 8 / 12 / 16 / 24 / 32 / 48 | `--sp-1` ~ `--sp-7` |

**字重只有 3 档不是偷懒**：系统字体栈上 800 / 820 / 850 / 900 的渲染宽度完全一致
（实测都是 206.39px），写 11 档等于写了 3 档，还让代码看起来比实际精细。

**字号收敛的收益**：改版前 43 个声明值里有 3 个（10 / 10.5 / 11）挤在 1px 内、
占了 77 个元素，全站 93% 的文字挤在 11–13.4px 这 2.4px 区间里。收敛到 7 档之后，
标题和正文的层级才真的读得出来。

**热力图色阶有个坑**：`td.cell` 的 `color` 特异性是 (0,2,2)，裸 `.lv3` 只有 (0,1,0)，
会被压死。所以色阶必须写成 `table.hm td.cell.lvN`，并且色值走 `--lvN-bg` / `--lvN-fg`
变量（图例的小色块共用同一套）。

### 卡片高度的一致性

| 网格 | 改版前 | 改版后 |
|---|---|---|
| 工具库 `.tcard` | 158px 恒定 | 158px 恒定 |
| 组合方案 `.bcard` | 725–792px（差 67） | **501px 恒定** |
| AI 测试 `.atcard` | 434–597px（差 163） | **225–285px（差 60）** |
| 优惠白嫖 `.ftcard` | 418–457px（差 39） | 418–457px（差 39） |

组合卡和 AI 测试卡都用了 `<details>` 折叠：默认只显示「是什么、多少钱、几维打分」，
理由、优缺点、怎么用这些展开才看。折叠区是原生 `details/summary`，键盘和屏幕
阅读器都直接支持，不需要额外的 aria。

点开是 3 列网格（16 项全可见），点任一项自动收起。侧栏高度从 350px 降到 48px。

## 定期更新（哪些自动、哪些必须人工）

| 事项 | 谁保证 | 频率 |
|---|---|---|
| 新闻 RSS 抓取、去重、标题过滤 | ✅ 自动（`scripts/refresh.js` + GitHub Actions） | 每周一 |
| 价格页有没有变（指纹） | ✅ 自动告警 | 每周一 |
| 数据新鲜度（>30 天标黄） | ✅ 自动（`_refresh-report.json` + 页面） | 每次构建 |
| 首购优惠过期 | ✅ 自动（`build.js` 拦截 `ends`） | 每次构建 |
| 改价、改额度、改限制 | ⚠️ 人工核对官网后改 JSON | 看到告警时 |
| 人工新闻的「对测试的影响」 | ⚠️ 人工 | 每周挑 1–2 条 |
| 角色渗透度 / 替代度 | ⚠️ 人工判断（页面已标「本站判断」） | 每季度 |

自动任务只写 `data/news-auto.json`、`data/_price-snapshots.json`、`data/_refresh-report.json`，
**不碰** `tools.json` / `plans.json` / `promos.json` / `news.json`。

想脱离 GitHub Actions 用系统定时，Windows 任务计划程序（路径换成你自己的仓库位置）：

```
程序：node
参数：<仓库路径>\scripts\refresh.js
起始于：<仓库路径>
```

Linux / macOS 用 cron 同理，先 `cd` 到仓库再 `node scripts/refresh.js`。

维护、发版、回滚的完整流程见 [docs/MAINTAIN.md](docs/MAINTAIN.md)；
站点以 GitHub Pages 发布，推送到 `main` 即自动重建并部署（见 `.github/workflows/pages.yml`）。

## 已知限制

- **价格只覆盖公开档位**。企业版、团队版、私有化部署没有逐项收录；它们的价格通常是「联系销售」。
- **报价制产品的区间不是标价**。testRigor / mabl / QA Wolf 的托管服务仍是报价制，站内数字来自第三方口径，只用于预算量级。
- **评分与渗透度是判断，不是跑分**。9 个维度、角色渗透度、替代度都是编辑判断；页面标了「本站判断」，依据写在卡片里。
- **自动新闻没有人工判断**。自动条目只保证来源与时间，不保证 relevance；默认不显示，需要手动打开「含自动抓取」。
- **部分海外源会 403 / 超时**。运行报告里如实记录；这会影响自动条目的覆盖，不影响人工条目。
- **汇率是固定值**。美元按 7.25 折算，只用于同表比较；真实支付价随汇率与税费变化。
- **能力分不等于实测**。它回答「这个工具能不能干这类活」，不回答「在你的仓库里干得好不好」。
- **角色阶梯是地图，不是 JD**。不同公司同名岗位职责差异很大；用它定位，不要用它谈薪。
