# DESIGN v8 · 站务层与动效刻度

> 日期：2026-11-02 ｜ 前置：`docs/DESIGN-v7.md`（深色数据台）｜ 实现：`src/v8.css`（最后叠加层）
> 范围：新增站务层组件、把散落的动效数值收成 token、首屏骨架。**不重做 v7 的视觉方向。**

---

## 1. 为什么有这一层

v7 定下了整站视觉（深石墨底、玻璃卡片、青紫强调、12–16px 圆角），但有三件事没解决：

1. **新页面缺组件。** 搜索页、个人中心、反馈、静态页、出错页在 v7 里没有对应样式，直接拼 v5/v7 的旧类会得到一堆不一致的间距与层级。
2. **动效数值散落。** `0.15s` / `.16s` / `.22s` / `.26s` / `.34s` / `.38s` / `.4s` 各写各的，
   `cubic-bezier` 出现五套。改一处缓动要全局搜。
3. **首屏有真实空白。** 单文件是 900KB 量级的 HTML，从解析到首帧渲染之间是白屏——
   这段等待真实存在，但没有东西盖住它。

v8 只做这三件事。

## 2. 动效刻度（新增 token）

三档时长、三档缓动，全站只用这些。

| Token | 值 | 用在哪 |
|---|---|---|
| `--dur-1` | `180ms` | 反馈类：hover、按下、收藏切换 |
| `--dur-2` | `260ms` | 层级切换：抽屉、下拉、骨架淡出 |
| `--dur-3` | `420ms` | 入场：页面进入、卡片依次出现 |
| `--ease-out` | `cubic-bezier(.16,1,.3,1)` | 出场／入场（快起慢收） |
| `--ease-in-out` | `cubic-bezier(.4,0,.2,1)` | 位移与尺寸变化 |
| `--ease-pop` | `cubic-bezier(.2,1.4,.4,1)` | 只用一处：收藏按钮按下的回弹 |
| `--rise` | `8px` | 入场位移量 |

**为什么位移只给 8px**：入场动画的作用是「让人看出这是新内容」，不是表演。
位移超过 12px 时，视线要跟着移动才能读完，反而变慢。8px 足够被感知，又不打断阅读。

**为什么只要三档缓动**：缓动的区别在长动画里才看得出来。260ms 内的差别肉眼不可分辨，
多出来的档位只会让下一个人不知道该用哪个。

## 3. 站务层组件

| 组件 | 类名 | 说明 |
|---|---|---|
| 搜索大框 | `.sbig` | 聚焦时青色描边 + 3px 光晕；右侧 `Ctrl K` 提示 |
| 搜索分类芯片 | `.schips` / `.chip` | 复用全站 chip 样式，选中态加 `aria-pressed` |
| 搜索结果行 | `.sresRow` | 4 列网格（类型 / 名称 / 描述 / 动作）；窄屏收起描述列 |
| 工具结果行 | `.sresRow`（button） | 整行是按钮，点开详情抽屉，不跳页 |
| 个人中心卡 | `.mcard2` | 四张等高卡，内部可滚动，最高 340px |
| 列表行 | `.mrow` / `.mgo2` / `.mx` | 收藏与历史共用；`×` 是移除按钮 |
| 本地存储清单 | `.kvList .kv` | 三列：键名（等宽）/ 用途 / 当前值（截断） |
| 反馈类型卡 | `.fbk` | 2×2；选中态青边 + 青底 |
| 反馈模板预览 | `.fbPrev` | 等宽、预格式、最高 420px 可滚 |
| 静态页正文 | `.pageBody` / `.pgH` / `.pgP` / `.pgDL` / `.faqList` | 行宽限制 76–80ch，标题带分隔线 |
| 出错堆栈 | `.errTrace` | 等宽、最高 260px，可整段复制 |

**行宽为什么限制**：中文正文超过约 40 个汉字一行，回行时容易串行。
静态页是长文本页，所以 `.pgP` / `.pgDL` / `.pagePanel .ul` 都限了 `max-width`。

## 4. 动效清单（只列有动画的地方）

| 位置 | 动效 | 目的 |
|---|---|---|
| 首页光斑 `.hglow` | 22s 极慢漂移 + 缩放 1→1.06 | 建立「这是个活的界面」，不抢字 |
| 首页 h1 关键词 | 下划线 0.9s 从左扫过（延迟 0.28s） | 指向主行动，只在首屏进站时跑一次 |
| 首页轮播 `.hRot` | 每 2.8s 换一句，200ms 上移淡出/淡入 | 把「它能解决什么」变成会动的证据 |
| 页面入场 | `.phead` / `.panel` 依次 420ms 上移 8px | 引导视线自上而下 |
| 个人中心卡 | 四张卡依次错开 50ms | 建立顺序感 |
| 反馈类型卡 | 四张依次错开 45ms | 同上 |
| 列表卡片 | `.stagger > *` 每项 +50ms（v7 已有） | 列表可数 |
| 收藏按钮 | 按下缩放 0.88（`--ease-pop`） | 确认操作 |
| 首屏骨架 | 微光 1.25s 循环 + logo 脉冲 | 说明「在加载」而不是「坏了」 |
| 搜索结果分组 | 每次渲染 420ms 上移 | 说明「这组是新出的」 |

**刻意没做的动效**：滚动视差、鼠标跟随、粒子、打字机效果。
它们会让页面看起来更「炫」，但都不服务于理解，而且都会和 `prefers-reduced-motion` 打架。

## 5. 首屏骨架

```
HTML 已解析 ──[骨架可见]──► init() 跑完 ──[淡出 260ms]──► 摘除节点
```

规则：

- 骨架只在 `html.js`（JS 可执行）下显示 → **禁用 JS 的用户不会看到一块永远不消失的灰板**；
- `init()` 结束时 `html.ready` → 透明淡出 → 320ms 后把节点从 DOM 摘掉；
- head 里有 4 秒兜底定时器：即使初始化抛错在加 `ready` 之前，也强制揭开，绝不锁死；
- 打印媒体里 `#boot` 直接 `display:none`（它是 `position:fixed` 全屏层，透明也会占住首页）。

## 6. 可访问性

- 42 个视图 × 深 / 浅双主题对比度 **0 违规**（`scripts/a11y-audit.js`）。
- 所有新组件都有 `:focus-visible` 焦点环（青色 2px + 3px offset）。
- 收藏按钮带 `aria-pressed`，类型芯片带 `aria-pressed`，搜索分类带 `role="group"`。
- `prefers-reduced-motion: reduce` 下：光斑、下划线、轮播脉冲、骨架微光、全部入场动画**一律静止**，
  光斑降到 55% 不透明度保留环境感。这条不是可选项。
- 状态不只用颜色表达：错误用「！」，成功用「✓」，过期用文字「已过期」。
- 静态页正文用 `<dl>` / `<details>` 等语义标签，不是一堆 `<div>`。

---

## 7. 实现

- 构建顺序补第 7 层：`styles → v4 → v4-responsive → v5 → v6 → v7 → v8`。
  **v8 必须最后**：它要覆盖 v7 的圆角与间距细节。
- 新增页面全部由 `data/pages.json` 与 `data/nav.json` 驱动，v8 只提供外观，不含文案。
- v7 未改动；v8 只新增类，不复写既有组件。

## 8. 已知取舍

1. **v8 仍是叠加层**，底层有 v1–v7 的 DOM。少数 v5 硬编码颜色仍需 `!important` 覆盖，
   后续若继续迭代，建议把组件样式逐步收敛。
2. **动效 token 只在新代码里强制**，旧的 `.15s` 字面量仍在 v4–v7 中存在，属于历史遗留，
   不影响观感一致性（时长差异在 180ms 量级上不可察）。
3. **浅色主题下骨架的灰阶对比偏弱**（`rgba(14,30,55,.07)`），因为它只出现 300ms 左右，
   刻意不做强对比，避免闪一下更显眼。
