# AI Test Stack · v4 产品判断与需求（先看这一份）

> 写于 2026-11-01，基于 v3 现状（提交 8da1dd9）的实际走查与同行核验。
> 结论先行：**站点该做，但不能再往"更多页面"的方向长。v4 只补一条断掉的链——从"选什么"到"怎么开始"。**

---

## 一、有意义吗

有，但价值不在"资讯"上。三条证据：

1. **同行的排名是买来的。** 查证 itechguides / positioniseverything 的 AI 测试工具榜，每个名次下面挂 `For vendors · Sponsor this spot · $149/mo`——排序位明码标价。这意味着"无赞助、可核对、能指回官网链接"在事实上是稀缺位。
2. **国内那一半没人写。** 英文站覆盖 testRigor $300/月、mabl 报价制，对"火山方舟 ¥40""GLM Coding Lite ¥118""数据是否用于训练""429 限流窗口"零覆盖。国内测试工程师真正要决策的字段，恰好都在这一半。
3. **清单是红海，结算是空白。** GitHub `ai-testing` 话题下 807 个仓库、`awesome-ai-testing` 把工具清单做到极全——说明"列工具"这件事已经饱和。但没有人回答"我这套组合一个月多少钱、能不能进我的 CI、额度够不够我跑夜里的回归"。**本站的位置是结算台，不是货架。**

## 二、能做下去吗

能，但要先承认三个硬约束，否则做三个月就会烂掉：

| 约束 | 现实 | 应对（v4 落地的） |
|---|---|---|
| 数据维护成本 = 产品天花板 | 12 档套餐 × 4 个易变字段，一个人手动核验，30 天一轮已是极限 | 把"过期"做成可见事实：每条价格带核验日 + 源链接 + 已过天数，超 45 天自动标黄。不假装永远新鲜 |
| 一次性工具没有留存 | 用户买完就走，没有任何理由回来 | 唯一的钩子是"资产"而非"内容"：方案书可导出、30 天清单可勾选、接入骨架可复制 |
| 结论要能背锅 | 评分是编辑判断，一旦有人照它花钱出错，信誉归零 | 每条结论旁必须有"什么情况下这条不成立"；评分口径页保留，不删 |

## 三、缺什么（按重要性排，全部来自实际走查）

1. **链路是断的。** 诊断 → 采纳，只把"壳"塞进我的组合：套餐没进、成本没联动、额度没算。用户点完"采纳"看到的是一个不完整的账。
2. **拿到方案之后无事可做。** 全站到"推荐一套组合"为止。测试负责人真正的下一个动作是——写给领导审批、然后第一周开始接进流水线。站内没有出口。
3. **信任颗粒度不够。** 全站只有一个"数据核验日"，单条价格无法追溯，也无法判断哪条最可能过期。
4. **信息被做成了装饰。** "完整工具站"16 张卡，每张两行、第二行被 `…` 截断——等于花了 16 个格子的面积传递 0 条新信息。
5. **没有导出。** 结论只能在浏览器里看，不能带走。
6. **诊断台没有退路。** 想直接看全部组合的人，必须先把 3 道题点完。
7. **答过的题不记忆。** 刷新即失，只有"存档"那一步才落 localStorage。

## 四、v4 需求（只做 P0，全部可在单文件离线约束内完成）

| 编号 | 需求 | 验收口径 |
|---|---|---|
| R1 | 诊断台出结果时补三块：成本拆解（壳/电分列）、额度够不够（按套餐窗口算一次）、升级路径（多花 ¥X 能换到什么） | 报告里同时出现壳价、电价、总额、额度结论、≥1 条升级项 |
| R2 | 采纳闭环：一次带壳 + 带套餐 + 带成本落到「我的组合」，并在页面上高亮"套餐已同步" | 采纳后 `ats_stack` 同时含 tool 与 plan，月成本随之变化 |
| R3 | 新增 `#plan` 执行包页：方案 → 4 周动作表（每周 1–2 个动作 + 验收标准 + 预计耗时），进度可勾选、可导出 Markdown | 未选方案时给空态引导；有方案时 4 周 ≥8 个动作；勾选后刷新仍保留；导出内容含成本表与动作表 |
| R4 | 价格溯源：每档价格显示核验日、源链接、"已核验 N 天"，>45 天标黄 | 套餐表 12 行每行都有可点的源链接与天数 |
| R5 | 完整工具站改"规格表"：一行一个功能，含序号、模块、不截断的一句话、直达 | 17 行，描述完整显示无省略号，搜索/筛选保留 |
| R6 | UI 重做：从"卡片汤"改为"报告台"——发丝线分隔的 sheet、拉开的字号阶梯、语义化的三色（结论/风险/通过）、去掉全部径向渐变与圆角辉光 | 对比度审计双主题 0 违规；三档视口无横向溢出；首屏不出现两层卡片嵌套 |

**明确不做**（避免又长成四不像）：测试社区、账号体系、后端、真实大模型诊断（违反离线约束）、自动抓价（国内定价页多为 JS 空壳，抓不到）。

## 五、UI 设计判断（对 v3 实拍的逐条否定）

| v3 现状 | 为什么不好 | v4 改法 |
|---|---|---|
| 所有容器同一个模子：14px 圆角 + 1px 描边 + 同样 padding | 没有节奏差，读起来像后台管理界面，不像"给结论的东西" | 数据区改 sheet（连续面板 + 发丝分隔线，无圆角无阴影）；只有可点的一等对象才用卡片 |
| 青色一色多用：链接、按钮、数值、标签、选中态全是它 | 语义塌陷，用户无法从颜色判断"这是可点的"还是"这是结论" | 三色分工：青=可交互，琥珀=结论/钱，玫红=风险；通过态用绿 |
| 字号只有两档在跑（27px 标题 / 12–13px 正文） | 读数不"读数"，标题不"标题" | 五档拉开：64 / 30 / 17 / 14 / 11；所有数字用 tabular-nums + 单位小字 |
| 背景三层径向渐变（v2 极光残留） | "AI 模板味"的主要来源，且与"仪器"定位矛盾 | 全删。改一层极淡点阵 + 顶部 1px 光边 |
| 卡片文案被 `…` 截断 | 把信息做成装饰 | 规格表：全量显示，行高换信息量 |
| 诊断台只有一行 chips，下方大片空 | 首屏重心失衡 | 选项改整行按钮（A/B/C/D + 悬停），面板高度由 3 步进度条撑住 |

## 六、验收由谁画句号

自动化 5 项 + 人工 4 项，逐条落 `docs/ACCEPTANCE-v4.md`：

- 自动：构建 exit 0 / 对比度双主题 0 / 端到端断言全过（v4 扩到 18 组）/ 三档视口无溢出 / 断网 file:// 可开
- 人工：①3 问→报告→采纳→执行包 走通且账目对得上；②导出的 Markdown 能直接贴进审批邮件；③浅色主题下读数与结论仍清晰；④"领导视角"：不看说明能否在 30 秒内说出"这套要多少钱、为什么"。
