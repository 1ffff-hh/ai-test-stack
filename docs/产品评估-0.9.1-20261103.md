# AI Test Stack · 产品评估与需求终稿（0.9.1）

评审角色：资深产品。评审对象：`ai-test-stack` v2.3.0（交接报告 `HANDOFF.md` + `errors.log`）。
评审日期：2026-11-03。同行调研来源见第 6 节。

---

## 1. 结论先行

| 问题 | 判断 | 依据 |
|---|---|---|
| 有没有意义？ | **有，但意义不在「又一个价格表」** | 同类站（llmrates、codingplan.link、pricepertoken）都在做「价格 + 额度」，本站的差异化是**把选型串成决策链**：你是谁（角色/能力）→ 该配什么（组合）→ 花多少钱（套餐）→ 怎么落地（30 天执行包）→ 怎么交差（可打印报告）。这条链没人做，且只有测试工程师写得出来 |
| 能不能做下去？ | **能，但只能按「单人 + 静态站 + 周更」的节奏做下去** | 现状已具备：55 个数据文件、42 视图、四道门禁、三条 CI（部署/周更/探活）、零后端零依赖、可离线。做不下去的形态是「追热点、日更、做社区」 |
| 最大的风险是什么？ | **数据时效**，不是功能不够 | 2026-10 到 11 一个月内：Cursor 改价、Copilot 转 credits、Claude Max 打包 API 额度。价格站一旦过期就是误导。本站已有核验日 + 来源等级 + 指纹告警，但仍靠人工核价 |
| 上一版（v2.3）真正的问题 | **不是缺功能，是「看着廉价」** | 实测：22.1% 的文本低于 11px；三档视口全部横向溢出；浅色主题渐变标题 1.29:1；选中态两套语言。功能页 42 个已经够了 |

**一句话**：这个站的天花板不是「功能数量」，而是**可信度 + 可读性 + 可复用性**。功能再加下去只会稀释这两样。

## 3. 缺口清单（按「值不值得做」排序）

### P0 · 不做就掉信誉（本期已做）

| # | 缺口 | 为什么是 P0 | 本期处置 |
|---|---|---|---|
| 1 | 可读性地板 | 8px 的文字在 1080p 笔记本上读不出来，用户第一反应是「这站不专业」 | 全站最低 11px，并写成门禁断言 |
| 2 | 浅色主题不可用 | 渐变标题 1.29:1、诊断台是深色孤岛——而浅色是「白天上班打开」的主场景 | 浅色实色标题 + 卡片跟随主题；审计补渐变分支 |
| 3 | 横向溢出 | 三档视口全溢出，移动端体验直接扣分 | hero 裁剪 + 按三个动画相位断言（旧断言取样太早放过了它） |
| 4 | 决策表埋在第 2876px | 用户来是为了「这 57 档怎么选」，却要滚两屏才看到表 | 层级重排：口径 → 结论 → 表 → 细节 → 阶梯（折叠） |
| 5 | 表格不能排序 | 同类站第一屏就是可排序矩阵，我们只有编辑视角的加权分 | 月价/综合分可点排序 + 吸顶表头 + `aria-sort` |
| 6 | 文案写死「7 个模块」 | 站规明写「计数不写死」，自己违反自己的规矩 | 运行时算 + 断言 |

### P1 · 决定能不能被引用/被搜索到（下期做）

| # | 缺口 | 同行参照 | 建议做法 |
|---|---|---|---|
| 1 | **每元额度当量**（订阅 vs 按量的等效折算） | llmrates 的 `Equivalent API value` / `Value multiple` 是它最被引用的一列 | 需要按模型的 token 单价数据。**不能凭空造**：先补 `data/api-pricing.json`（来源等级同套餐），再在套餐表加一列；缺数据的档位显式标「厂商未公布」 |
| 2 | **移动端表格卡片化** | 数据密集站的通行做法：≤760px 把行重排成带标签的卡片 | `td::before{content:attr(data-label)}`，表头隐藏，保留排序 |
| 3 | **价格变动的主动推送** | revexos 记录 306 次改价；本站有 `plans-history` 但没有「本周变了什么」的入口 | 用现成的 `feed.xml` + 新增 `#changes`（只列指纹变化 > 5% 的档），配合每周 CI |
| 4 | **图标/标识系统** | 同类站用厂商 logo；本站刻意零图片资源 | 保持零图片，但把 Unicode 图标换成**内联 SVG sprite**（仍是单文件），解决「◉ ◈ ⊞ 混用不成体系」的问题 |
| 5 | **可分享的深链状态** | 同行普遍把筛选写进 URL | 完整工具站的分类 tab 与套餐排序写入 hash（`#all?tab=tool`、`#plans?sort=price`），交接报告已列为待确认第 11 条 |

### P2 · 想做但先别做

| # | 项 | 为什么先别做 |
|---|---|---|
| 1 | 测试社区本体 | 单人无法维持内容质量；先保留 `nav.json` 的 `reserved` 占位 |
| 2 | 账号 / 跨设备同步 | 破坏「零后端、可离线」这条最硬的差异化；要做也是「导出 JSON 自己存网盘」 |
| 3 | 自动改价 | 解析会把「$20 起」读成「$20」，错一次就毁掉整站的可信度；维持指纹告警 + 人工核价 |
| 4 | 薪资 / JD 采样 | 没有可靠公开源，写了就是编 |

## 4. 最终需求（V2.4 已实现部分 = 验收口径）

1. **可读性**：任何可见文字的计算字号 ≥11px；表格数字用等宽数字并按数值对齐；正文行宽 ≤68ch。
2. **一致性**：选中态全站只允许一套视觉语言（主动作色描边 + 着色底），并必须有可区分的 `:focus-visible`。
3. **主题**：深/浅两个主题都必须完整可用；不允许「某块永远深色」；渐变文字必须通过对比度审计（大字 3:1、正文 4.5:1）。
4. **布局**：1440 / 820 / 390 三档在任何时刻（含动画相位）不得出现文档级横向溢出。
5. **层级**：任何页面的**首要决策面**必须在首屏之后 1 屏内可达；装饰性视图不得挤占它。
6. **数据诚实**：计数一律运行时算；缺数据显式标「厂商未公布」；核验新鲜度必须在数据表旁边可见，而不是只写在数据健康页。
7. **可维护**：以上 1–6 必须落成 `verify.js` / `a11y-audit.js` 断言，不能只写在文档里。

## 7. 需要用户拍板的三件事

1. **P1-1 当量列要不要做**：它需要新增一份按模型 token 单价的数据（人工核价成本约 2–3 小时/次）。做 → 本站最有引用价值的列出现；不做 → 维持现状，靠额度口径描述。
2. **P1-5 深链**：把 tab/排序写进 URL 会改变分享链接的既有约定，需要回归 `syncHash()`。
3. **交接产物落位**：`HANDOFF.md` 与 `errors.log` 现在仓库根，含本机绝对路径，使 `check-pii` 恒为 68 处命中（`npm run check` 因此在第二步中断）。移进 `docs/internal/`（已在扫描白名单里）即可恢复全绿——这一步按交接报告第 13.3 节属于「做之前必须先问」。
