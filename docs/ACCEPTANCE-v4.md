## 4. 本次抓出并修复的缺陷（验收的价值所在）

### 4.1 报告页错账（严重）
- **现象**：成本拆解显示「壳 ¥60 / 电 ¥40 / 合计 ¥40」。
- **根因**：`tools.json` 的 `monthlyCost` 是"自备 API 的参考花费"，`bundles.json` 的成本口径是"开源壳算 ¥0"。两套口径混用。
- **修复**：新增 `shellCost()` 统一口径（闭源才计费），报告、组合、导出三处共用；并在 verify 第 12 组加"壳+电=合计"的自证断言，防止再犯。

### 4.2 390px 横向溢出 8px
- **根因**：`.diag` 用 `margin:0 -22px` 做出血，而移动端容器内边距只有 14px。
- **修复**：移动端取消负边距；verify 第 6 组恢复三档全 true。

### 4.3 首页模块格描述丢失
- **根因**：`mcardHtml` 的 slim 分支不输出 `tagline`，v4 又隐藏了"N 个功能"，导致六格只剩标题。
- **修复**：slim 也输出描述；emoji 改为序号（9.5px 下 emoji 只剩彩色噪点）。

### 4.4 审计 0/0 的可信性
- **做法**：向 `v4-responsive.css` 末尾追加 5 条低对比规则 → 审计抓到 `dark total 2`、`light total 1`（选择器 `.q`、`.sdesc`，均为 v4 新组件）→ 清除 → 恢复 0/0。
- **记录**：`.drrow p`、`.task p` 未被抓到，因为审计只加载页面默认态（报告态/有任务的执行包不出现）。这是审计器的**状态盲区**，不是 0/0 造假。

### 4.5 verify 与新结构调整同步
- 「完整工具站」从 16 张卡改成 17 行规格表 → 断言从 `.acard/16` 改为 `.srow/17`；404 链接数 16→17；诊断按钮数 3→4。**断言跟着改是对的，但不能为了过而放宽**——所以新增了 13、14 两组更严格的端到端断言。

## 5. 已知限制（不掩饰）

1. **移动端首屏看不到报告**：诊断台在标题之后，390px 下要滚屏。取舍是"先讲清是什么，再出结果"，未做折叠。
2. **审计器有状态盲区**：只检测页面默认态的可视文本，报告态/勾选态不覆盖。
3. **无像素级视觉回归基线**：`docs/shots/` 是人工基线，没有自动 diff。
4. **数据仍需人工核验**：12 档套餐的核验日统一为 2026-10-29，超过 45 天会自动标黄，但不会自动更新。
5. **`planpack.json` 的动作是通用方法论**，不随壳的差异变化（只有 CLI 名与 Base URL 是动态的）；换壳不换动作表。

## 6. 明确未做（有意识留白）
